# Vilra — Руководство

Vilra — локальная галерея для просмотра изображений, тегирования и быстрого отбора по папочным и ручным тегам. Приложение хранит индекс, теги и состояние сессии в локальном SQLite-файле; рядом с фотографиями создаются только миниатюры.

## 1. Установка

Vilra 0.2.1 распространяется как alpha для Linux x86-64 и Windows x64 через [GitHub Releases](https://github.com/saidovux/vilra/releases).

Linux:

```bash
chmod +x Vilra_0.2.1_amd64.AppImage
./Vilra_0.2.1_amd64.AppImage
```

Windows: запустите `Vilra_Setup_0.2.1_x64.exe`. Инсталлятор пока не подписан, поэтому SmartScreen может показать предупреждение. Не отключайте системную защиту; сверьте файл с `SHA256SUMS.txt`.

Поддерживаемые форматы: `jpg`, `jpeg`, `png`, `webp`. Для сообщения об ошибке используйте [GitHub Issues](https://github.com/saidovux/vilra/issues) и укажите ОС, версию Vilra и шаги воспроизведения.

Для сборки из исходников нужны Node.js 22+, npm, stable Rust/Cargo и platform build tools. Windows installer собирается на Windows x64 с MSVC Rust toolchain.

Desktop-запуск из исходников:

```bash
npm ci
npm run dev
```

Сборка Linux AppImage:

```bash
npm run build:linux
```

Сборка Windows NSIS installer на Windows:

```powershell
npm run build:win
```

Electron хранит `tagimage.sqlite` в системном каталоге данных приложения, запускает три Rust sidecar-процесса и останавливает их вместе с окном. Python в desktop runtime не используется.

## 2. Browser Dev Runtime

```bash
./start.sh
./start.sh /home/user/Pictures
./start.sh /home/user/Pictures --port 9000
./start.sh status
./start.sh stop
./start.sh restart
./start.sh logs
```

При запуске с аргументом папка открывается сразу. Без аргумента путь можно указать в интерфейсе.

Этот режим предназначен для разработки, E2E и диагностики. Основной пользовательский runtime запускается через Electron.

Проверка Rust thumbnails в строгом режиме:

```bash
./start.sh start --build-rust --strict-rust
```

Browser/E2E regression tests:

```bash
npm run test:e2e
```

E2E tests use generated fixture images in `.run/e2e-images`, an isolated SQLite file in `.run/e2e/`, and stop `start.sh` processes during teardown.

`start-webapp.sh` оставлен как deprecated compatibility wrapper на `./start.sh`.
`worker-rust-thumb.sh` оставлен как ручной debug helper для отдельного запуска Rust thumb worker.

## 3. Live-Синхронизация

Rust backend рекурсивно следит за выбранными папками и поддерживает форматы:

`jpg`, `jpeg`, `png`, `webp`

При создании, удалении, переименовании, перемещении или изменении файла Vilra обновляет только затронутые записи SQLite и thumbnail jobs. Интерфейс получает изменения через SSE без Refresh и ручного Rescan.

При запуске выполняется автоматическая сверка сохранённых roots:

- неизменившиеся файлы сравниваются по `path`, `size` и `mtime` без повторного декодирования;
- новые и изменённые изображения upsert-ятся в SQLite по паре `root_path + relative_path`;
- все родительские папки становятся автоматическими тегами;
- ручные теги сохраняются;
- отсутствующие на диске файлы скрываются из выдачи;
- миниатюры создаются в `.imgindex/thumbs/` с сохранением исходных пропорций.

Если root временно недоступен, записи не удаляются: библиотека получает offline-статус. Периодического полного сканирования нет.

Пример:

```
/photos/
├── travel/
│   └── italy/
│       └── rome.jpg
└── portraits/
    └── anna.webp
```

`travel/italy/rome.jpg` получит авто-теги `travel` и `italy`.

## 4. Галерея

Карточки показываются в masonry-сетке. Миниатюры не обрезаются: портретное изображение остается портретным, квадратное остается квадратным, панорамное остается панорамным.

На карточке отображаются:

- имя файла;
- автоматические теги папок;
- ручные пользовательские теги.

## 5. PreviewModal

Клик по карточке открывает canvas-просмотрщик `PreviewModal`.

Доступно:

| Действие | Управление |
|---|---|
| Предыдущее / следующее | кнопки `‹` / `›` или стрелки клавиатуры |
| Закрыть | `Esc`, кнопка `×`, клик по фону |
| Открыть оригинал | кнопка `Оригинал` |
| Масштаб | колесо мыши |
| Панорама по изображению | drag по canvas |
| Быстрое увеличение | click без drag по canvas |
| Добавить тег | поле тегов или раскрываемый список тегов в нижнем dock |

## 6. Теги

Есть два типа тегов:

| Тип | Источник | Можно удалить вручную |
|---|---|---|
| Автоматические | имена родительских папок | нет |
| Ручные | поле добавления тега в preview | да |

Автоматические и ручные теги участвуют в поиске одинаково. При переименовании папки автоматические теги пересчитываются сразу, а ручные теги и ID изображений сохраняются.

## 7. Поиск, Анти-Список И Вкладки

В каждой вкладке есть один общий ввод тегов и два набора выбранных тегов:

| Набор | Поведение |
|---|---|
| Теги | `tag` добавляет обычный тег |
| Анти-список | фото скрывается, если содержит хотя бы один анти-тег |

Анти-тег вводится как `!tag` или `-tag`. Если тот же тег добавляется в противоположную группу, он переносится туда.

Режимы совпадения:

| Режим | Поведение |
|---|---|
| Любой | фото содержит хотя бы один обычный тег; это режим по умолчанию |
| Все | фото содержит все обычные теги |

Фокус на поле поиска показывает доступные теги под ним. Выбор подсказки добавляет обычный тег или анти-тег в зависимости от введённого префикса.

В настройках доступна полноценная зона управления тегами: создание, поиск, сортировка, цвет как метаданные, rename/delete для ручных тегов и счетчики связей. Папочные теги выглядят как обычные, но защищены от rename/delete, потому что пересоздаются из структуры папок.

Поля ввода тегов используют fish-style автоподстановку: ghost-подсказку можно принять через `Tab` или `ArrowRight`, `Enter` добавляет текущий тег. Префиксы `!` и `-` поддерживаются в автоподстановке.

Вкладки работают как вкладки браузера: `+` создает новую вкладку в дефолтном состоянии, то есть без фильтров и с показом всех изображений.

Сессия сохраняется в SQLite:

- последняя открытая папка;
- все вкладки;
- include/exclude фильтры каждой вкладки;
- режим совпадения каждой вкладки;
- активная вкладка;
- последнее открытое изображение вкладки, если preview был открыт.

## 8. Структура Данных

SQLite содержит таблицы:

- `images` — путь, размер, mtime, ширина, высота, путь миниатюры, статус скрытия;
- `tags` — уникальный пул тегов;
- `image_tags` — связь изображения с тегом и типом `auto` / `user`;
- `app_session` — единственная локальная сессия приложения, включая вкладки.

Файлы рядом с фотографиями:

```
/photos/
├── .imgindex/
│   └── thumbs/
│       ├── abc123.jpg
│       └── def456.jpg
└── ...
```

## 9. Неполадки

SQLite DB недоступна или не инициализирована:

```bash
./scripts/repair-db.sh
./scripts/check-db.sh
```

Проверить путь к БД:

```bash
echo "$TAGIMAGE_SQLITE_PATH"
```

Пересоздать миниатюры:

```bash
rm -rf /путь/к/фото/.imgindex/thumbs
./start.sh /путь/к/фото
```

Browser runtime использует file-based SQLite через `TAGIMAGE_SQLITE_PATH`, по умолчанию `.run/tagimage.sqlite`. Electron использует app-data `tagimage.sqlite`, если override не задан.

Vilra остается локальным приложением: без аккаунтов, загрузок файлов на серверы и публичного веб-деплоя.

## 10. Проверки

Rust tests используют временные SQLite-файлы и временные image roots. Browser E2E запускаются командой `npm run test:e2e` и проверяют live create/delete/rename/move/modify без ручного обновления.
